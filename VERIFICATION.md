## Предыдущая проверка режима Мессенджера

Проверено в среде Python 3.12.14:

- `python3 -m unittest discover -s tests -q`: **60 тестов, OK**.
- `python3 -m shiftbot --config config.example.toml --validate`: успешно, без обращения к API.
- `python3 -m shiftbot --config config.example.toml --demo`: отсутствие смены и вчерашняя смена дают `not_open`, своевременное открытие — `on_time`, позднее — `late_open`.
- `python3 -m compileall -q shiftbot tests`: успешно.
- Docker-образ из приложенного Dockerfile собран успешно.
- `--validate` и `--demo` в контейнере с корневой файловой системой только для чтения: успешно.
- Запись, чтение и закрытие SQLite в volume от пользователя контейнера UID 10001: успешно.
- Синтаксис Docker Compose с тестовым файлом переменных: успешно.

Локальная HTTP-проверка проводит сценарий с форматами iikoServer и Яндекс Bot API: назначение ответственного → отсутствие открытия →
одно первичное сообщение → позднее открытие → сообщение с фактическим временем →
перезапуск с сохранённой SQLite без повторной тревоги. Внешние сервисы в этом сценарии не вызываются.

**Реальные iikoServer / iikoChain и Яндекс Мессенджер пока не подключены.** Не проверены ваши UUID предприятий,
доступы, соответствие часового пояса ответов и задержка передачи открытых смен на сервер.
Эти параметры проверяются на пилотной точке через `--probe` перед постоянным запуском.

Реальные пароли и токены в комплект не входят.
