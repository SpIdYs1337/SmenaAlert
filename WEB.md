# Uppetit IT

Веб-панель и монитор смен работают в одном сервисе. Ubuntu-серверу нужен доступ к HTTPS API iiko и к SMTP для отправки писем. Для проверки входящих укажите доступный с Ubuntu IMAP-сервер.

## Запуск

1. Из каталога проекта скопируйте шаблон настроек администратора.

   ```bash
   cp .env.web.example .env.web
   chmod 600 .env.web
   ```

2. В `.env.web` задайте `PANEL_ADMIN_LOGIN` и `PANEL_ADMIN_PASSWORD`. Пароль должен содержать минимум 12 символов. Настройки iiko и почты вводятся после входа.

   Если `.env.web` создан из старого шаблона, удалите строку `PANEL_BIND=127.0.0.1` для доступа по адресу локальной сети.

3. Запустите контейнер с Docker Compose v2.

   ```bash
   docker compose --env-file .env.web -f compose.web.yaml up -d --build
   ```

4. На Ubuntu выполните `ip -br -4 addr show scope global` и возьмите IP интерфейса в вашей локальной сети. Например, для адреса `192.168.1.25/24` откройте `http://192.168.1.25:8080` с компьютера в той же сети. Для входа по HTTP используйте `PANEL_SECURE_COOKIE=0`.

Docker по умолчанию публикует порт `8080` на всех IPv4-интерфейсах Ubuntu. Доступ из других сетей задаётся их правилами маршрутизации и фильтрации. Если панель работает через HTTPS-прокси на том же сервере, задайте `PANEL_BIND=127.0.0.1` и `PANEL_SECURE_COOKIE=1`.

## Сотрудники и права

Верхнее меню показывает доступные сотруднику модули. Выберите **Администрирование → Сотрудники** и нажмите имя в списке. Рядом откроется карточка с логином, состоянием входа, правами и закреплённой техникой. В ней кнопка **Редактировать доступ** открывает настройки прав и временного пароля. По нажатию на своё имя в правом верхнем углу сотрудник открывает личный профиль. Если ему доступен инвентарь, здесь видны его устройства.

Администратор установки входит с логином и паролем из `.env.web`. Для учёта техники в разделе **Администрирование → Добавить сотрудника** достаточно имени. Сотрудник сразу появится в списке для выдачи. Чтобы дать ему доступ в панель, включите **Доступ в панель**, задайте логин и временный пароль от 12 символов, затем отметьте нужные права. При первом входе сотрудник задаст свой пароль.

Для базы знаний и IT-инвентаря доступны чтение и редактирование. Право редактирования включает чтение. Управление мониторингом даёт доступ к торговым точкам, получателям, почте, подключениям iiko и рассылке. Право администрирования даёт доступ ко всем разделам и управлению учётными записями.

Изменение прав, блокировка и сброс пароля завершают прежние сеансы сотрудника. После сброса снова требуется сменить временный пароль. Адреса для оповещений о сменах по-прежнему задаются в разделе «Получатели».

## База знаний и документы

Создавайте разделы кнопкой **Новый раздел** и отдельные документы кнопкой **Новая статья**. Статья может быть на верхнем уровне или в выбранном разделе. Стрелка слева от ветки сворачивает её подпункты. Поиск раскрывает ветки с совпадениями.

Редактор поддерживает заголовки, выделение текста, цитаты и списки. Поставьте курсор в нужное место и нажмите **Добавить фото** или **Добавить видео**. Фото JPG, PNG и WebP принимаются до 5 МБ. Видео MP4 или MOV с H.264 и WebM принимаются до 20 секунд и 20 МБ. Сервер проверяет длительность при сохранении. Docker-образ включает FFmpeg. Для локального запуска с загрузкой видео установите FFmpeg отдельно.

При импорте выберите родительский пункт и файл до 5 МБ. Панель сохраняет оригинал и создаёт отдельную редактируемую ветку. Заголовки и многоуровневые списки Word в DOCX, а также заголовки Markdown превращаются в подпункты. В TXT и текстовых PDF поддерживаются пронумерованные заголовки вида `1.` и `1.1`. Для TXT и Markdown используйте UTF-8. PDF со сканами сохраняется как оригинал, описание можно заполнить вручную. Docker-образ включает утилиту чтения PDF. При запуске непосредственно на Ubuntu она устанавливается командой `sudo apt install poppler-utils util-linux`.

## IT-инвентарь

1. В **IT-инвентаре** нажмите **Принять технику**. Укажите инвентарный номер, название, место и дату приёмки. Фото, серийный номер и заметку можно добавить по ситуации.
2. При первом вводе в эксплуатацию или выдаче со склада укажите **Срок эксплуатации, мес.** Панель считает дату окончания от первого ввода по календарю. Если в месяце окончания нет нужного числа, берётся последний день месяца. За 30 дней появится предупреждение. Для старых устройств можно указать срок в карточке с опорой на историю.
3. Нажмите **Переместить** в карточке устройства, укажите новое место и дату. Выдача, передача другому сотруднику и возврат на склад доступны там же. В **Истории устройства** видны дата приёмки, места, даты перемещений, ответственные и заметки. Старые записи без места помечены «Место не указано».
4. Фильтр **Принято** показывает технику до первого ввода. **В эксплуатации** показывает текущие рабочие устройства. **На складе** включает поступившую и возвращённую технику. Фильтр по сроку и поиск работают вместе с фильтрами состояния.

## Обновление на Ubuntu

Из каталога установленной панели выполните команды.

```bash
git pull --ff-only origin main
sudo docker compose --env-file .env.web -f compose.web.yaml up -d --build --wait panel
curl -fsS http://127.0.0.1:8080/healthz
```

`ok` подтверждает готовность панели. Версия приложения указана под названием. Compose использует настройки из `.env.web` и текущий том `panel_data`.

## Настройка и пилот

1. В **Настройки → Подключение iiko** добавьте HTTPS-адрес сервера с `/resto`, технический логин, пароль и часовой пояс данных. Кнопка **Проверить** проверяет авторизацию. Для чтения кассовых смен техпользователю нужны право просмотра смен `B_ACO` и доступ к нужному предприятию. [Права в iikoChain](https://ru.iiko.help/resources/Storage/archive/PDF/RU_iikoChain_8.1.pdf#page=775)
2. В разделе **Настройки → Отправка SMTP** укажите сервер, порт, тип TLS, адрес отправителя, логин и пароль. Для Яндекс Почты для бизнеса используйте `smtp.yandex.ru`, порт `465` с SSL/TLS и пароль приложения при таком способе входа. [Настройки Яндекс Почты](https://yandex.ru/support/yandex-360/business/mail/ru/mail-clients/others)
3. Сохраните параметры, нажмите **Проверить соединение** и отправьте **Тестовое письмо** на свой адрес. Статус **Принято SMTP** подтверждает приём письма сервером отправки. С подключённым IMAP получение можно проверить из панели.
4. В **Торговые точки** добавьте одну пилотную точку. Выберите предприятие из справочника iiko или вставьте UUID вручную. В **Обычная неделя** задайте повторяющийся график по МСК, включая выходные. Через **Разовое изменение → Добавить дату** укажите другое время или выходной только на выбранное число.
5. В **Получатели** добавьте сотрудников и закрепите за ними точки. Те же назначения можно менять в карточке точки. Письма отправляются только активным получателям выбранной точки, по одному на адрес.
6. Через 15 минут после открытия по графику в **Обзор** нажмите **Проверить сейчас**. Сверьте фактическое открытие с iikoFront, пока смена ещё открыта. Если Chain показывает запись только после закрытия, для тревог нужен источник, который видит открытие раньше. Ручная проверка обновляет статус. Выберите точку и нажмите **Предпросмотр письма**, чтобы открыть форму отправки.
7. После пилота в **Авторассылка** включите автоматическую отправку и добавьте остальные точки. По умолчанию монитор отбирает готовые к проверке точки каждые 30 секунд. Контрольная дата и график определяются по МСК. Пункт **Допуск 1 минута к графику открытия** засчитывает открытие до 09:01:00 включительно при графике 09:00.

Для проверки сервис читает кассовые смены через `GET /resto/api/v2/cashshifts/list`. Из `openDate` берёт дату и время фактического открытия, переводит их в МСК и сверяет первое открытие за этот день с графиком точки. [API кассовых смен iiko v2](https://ru.iiko.help/article/api-documentations/kassovye-smeny-v2/)

Панель запрашивает смены у iiko через 15 минут после времени открытия точки по графику. Для графика 09:00 первый запрос возможен с 09:15 МСК. При позднем открытии закреплённые ответственные получают письмо **Смена открыта с опозданием** с фактическим временем. Если iiko ещё не зафиксировал открытие за день, они получают письмо **Смена не открыта**. После успешной отправки панель учитывает уведомление за этот день и не дублирует его. При временной ошибке SMTP панель повторяет отправку, сверяя письмо с последней проверкой iiko.

## Статистика открытий

В **Мониторинг → Статистика** выберите период и торговую точку. Дэшборд показывает своевременные и поздние открытия, отсутствие открытия на момент последней проверки, ошибки iiko и среднее опоздание от графика. Нажмите на день, чтобы увидеть график, фактическое открытие и время проверки по каждой точке.

Отчёт использует сохранённые проверки, по одному результату на точку за день по МСК. Доля своевременных открытий рассчитывается по статусам **Вовремя**, **С опозданием** и **Без открытия**. История начинается с первой сохранённой проверки.

## Проверка входящих по IMAP

1. В разделе **Настройки → Входящие IMAP** укажите сервер, порт, шифрование, адрес ящика, логин и пароль. Для Яндекс 360 используйте `imap.yandex.ru`, порт `993`, SSL/TLS, полный адрес ящика в качестве логина и пароль приложения для почты. Разрешите IMAP в настройках почтового ящика. [Параметры Яндекс 360](https://www.yandex.ru/support/yandex-360/business/mail/ru/mail-clients/mail-clients-troubleshooting)
2. Нажмите **Сохранить IMAP → Проверить доступ**. Панель открывает папку «Входящие» в режиме чтения.
3. В карточке **Тестовое письмо** отправьте тест на адрес подключённого ящика. После статуса **Принято SMTP** нажмите **Найти во входящих**. Панель ищет это письмо по `Message-ID`. Если оно ещё в пути, повторите поиск из **Журнала писем**.

SQLite и ключ шифрования паролей сохраняются в томе `panel_data`. Для резервной копии сохраняйте том целиком, включая `.panel-key`. Один экземпляр сервиса должен работать с этим томом. При миграции заполните подключения и контакты в новой панели. Настройки старого режима Мессенджера хранятся отдельно.

## Демонстрация и остановка

Для демонстрации на Linux с Python 3.11 или новее используйте временные данные и имитацию iiko, SMTP и IMAP.

```bash
python -m pip install -r requirements-web.txt
python -m shiftbot.web --demo
```

Откройте `http://localhost:8080` на компьютере, где запустили демонстрацию.

Остановить рабочую панель можно без удаления данных.

```bash
docker compose --env-file .env.web -f compose.web.yaml stop panel
```
