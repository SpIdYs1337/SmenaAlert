# Контроль открытия iiko с отправкой через SMTP

Веб-панель и монитор смен работают в одном сервисе. Разместите его на сервере с доступом к HTTPS API вашего iikoServer или iikoChain и к SMTP организации.

## Запуск

1. Из каталога проекта скопируйте шаблон настроек администратора.

   ```bash
   cp .env.web.example .env.web
   chmod 600 .env.web
   ```

2. В `.env.web` задайте `PANEL_ADMIN_LOGIN` и `PANEL_ADMIN_PASSWORD`. Пароль должен содержать минимум 12 символов. Настройки iiko и SMTP вводятся после входа.

   Если `.env.web` создан из старого шаблона, удалите строку `PANEL_BIND=127.0.0.1` для доступа по адресу локальной сети.

3. Запустите контейнер с Docker Compose v2.

   ```bash
   docker compose --env-file .env.web -f compose.web.yaml up -d --build
   ```

4. На Ubuntu выполните `ip -br -4 addr show scope global` и возьмите IP интерфейса в вашей локальной сети. Например, для адреса `192.168.1.25/24` откройте `http://192.168.1.25:8080` с компьютера в той же сети. Для входа по HTTP используйте `PANEL_SECURE_COOKIE=0`.

Docker по умолчанию публикует порт `8080` на всех IPv4-интерфейсах Ubuntu. Доступ из других сетей задаётся их правилами маршрутизации и фильтрации. Если панель работает через HTTPS-прокси на том же сервере, задайте `PANEL_BIND=127.0.0.1` и `PANEL_SECURE_COOKIE=1`.

## Обновление на Ubuntu

Из каталога установленной панели выполните команды.

```bash
git pull --ff-only origin main
sudo docker compose --env-file .env.web -f compose.web.yaml up -d --build --wait panel
curl -fsS http://127.0.0.1:8080/healthz
```

`ok` подтверждает готовность панели. Версия приложения указана под названием. Compose использует настройки из `.env.web` и текущий том `panel_data`.

## Настройка и пилот

1. В **Подключение iiko** добавьте HTTPS-адрес сервера с `/resto`, технический логин, пароль и часовой пояс данных. Кнопка **Проверить** читает кассовые смены. Для техпользователя начните с права просмотра смен `B_ACO` и доступа к нужному предприятию. [Права в iikoChain](https://ru.iiko.help/resources/Storage/archive/PDF/RU_iikoChain_8.1.pdf#page=775)
2. В **Почта SMTP** укажите сервер, порт, тип TLS, адрес отправителя, логин и пароль. Для Яндекс Почты для бизнеса используйте `smtp.yandex.ru`, порт `465` с SSL/TLS и пароль приложения при таком способе входа. Параметры корпоративного SMTP уточняются у администратора почты. [Настройки Яндекс Почты](https://yandex.ru/support/yandex-360/business/mail/ru/mail-clients/others)
3. Сохраните параметры, нажмите **Проверить соединение** и отправьте **Тестовое письмо** на свой адрес. В журнале статус **Принято SMTP** означает, что сервер принял письмо. Получение проверьте в почтовом ящике.
4. В **Торговые точки** добавьте одну пилотную точку. Выберите предприятие из справочника iiko или вставьте UUID вручную. В **Обычная неделя** задайте повторяющийся график по МСК, включая выходные. Через **Разовое изменение → Добавить дату** укажите другое время или выходной только на выбранное число.
5. В **Получатели** добавьте сотрудников и закрепите за ними точки. Те же назначения можно менять в карточке точки. Письма отправляются только активным получателям выбранной точки, по одному на адрес.
6. В **Обзор** нажмите **Проверить сейчас**. Сверьте фактическое открытие с iikoFront, пока смена ещё открыта. Если Chain показывает запись только после закрытия, для тревог нужен источник, который видит открытие раньше. Ручная проверка обновляет статус. Иконка письма в строке точки открывает отдельную форму отправки.
7. После пилота в **Авторассылка** включите автоматическую отправку и добавьте остальные точки. По умолчанию проверка идёт каждые 30 секунд. Контрольная дата и график определяются по МСК. Открытие ровно по графику можно засчитывать своевременным отдельной настройкой.

Для проверки сервис читает кассовые смены через `GET /resto/api/v2/cashshifts/list`. Из `openDate` берёт дату и время фактического открытия, переводит их в МСК и сверяет первое открытие за этот день с графиком точки. [API кассовых смен iiko v2](https://ru.iiko.help/article/api-documentations/kassovye-smeny-v2/)

Пока время открытия по графику точки впереди, авторассылка ждёт. После наступления назначенного времени сервис ставит одно первичное оповещение на получателя, если iiko подтвердил отсутствие своевременного открытия. Если после тревоги iiko покажет фактическое открытие, придёт уточнение. Ошибка iiko отображается в панели отдельным статусом. При временных ошибках SMTP очередь повторяет доставку, а журнал показывает результат по каждому адресу.

SQLite и ключ шифрования паролей сохраняются в томе `panel_data`. Для резервной копии сохраняйте том целиком, включая `.panel-key`. Один экземпляр сервиса должен работать с этим томом. При миграции заполните подключения и контакты в новой панели. Настройки старого режима Мессенджера хранятся отдельно.

## Демонстрация и остановка

Для демонстрации на Linux с Python 3.11 или новее используйте временные данные и имитацию SMTP и iiko.

```bash
python -m pip install -r requirements-web.txt
python -m shiftbot.web --demo
```

Откройте `http://localhost:8080` на компьютере, где запустили демонстрацию.

Остановить рабочую панель можно без удаления данных.

```bash
docker compose --env-file .env.web -f compose.web.yaml stop panel
```
